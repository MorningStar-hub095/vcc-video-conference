## 一、项目现状体检

### 1.1 目录结构（有效工程部分）

| 路径                                               | 角色            | 说明                                                                          |
| ------------------------------------------------ | ------------- | --------------------------------------------------------------------------- |

### 1.2 技术栈与依赖

**服务端**：C++11 · Linux epoll（LT + EPOLLONESHOT）· pthread 线程池 · MySQL C API（`libmysqlclient`）· `libcrypt` 的 `crypt_r()`（bcrypt 密码哈希）  
**客户端**：Qt 5.12.11 Widgets · FFmpeg（H.264 编解码）· SDL2（音频播放）· Opus（48 kHz 音频编解码）· WebRTC VAD · OpenGL（YUV 渲染）  
**协议**：自定义二进制协议，`packdef.h` 定义 20 种包类型；客户端与服务端建立**三路 TCP**（信令 / 音频 / 视频），**全部走 8000 端口**

### 1.3 构建与启动

| 组件  | 当前构建方式                               | 问题                                                                                                                              |
| --- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 服务端 | 手工 `qmake` + `make`，或 `src/makefile` | `src/makefile` 是教学模板：`LIBRARY=-lpthread -lmysqlclient` **缺 `-lcrypt`**，bcrypt 链接必失败；根目录 `main.cpp` 是空桩，用根目录通配编译会得到「什么都不做」的可执行文件 |
| 客户端 | Qt Creator GUI 构建                    | 无命令行脚本；分发需 `windeployqt` + 手工拷 DLL                                                                                              |

启动方式：`./PlayerHallServer [port]`，默认 8000；无配置文件、无日志输出（所有 `printf` 均被注释），MySQL 连接失败时 `err_str()` 直接 `exit(-1)`。

## 二、阻碍部署的问题点与修复优先级

| 级别       | 问题                                                                                                                  | 影响                                   | 修复动作                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------- |
| **P0-1** | 项目**不是 git 仓库**（`git rev-parse` 失败）                                                                                 | 无版本、无回滚基线、无法回答"有没有未提交改动"、协作必冲突       | 立即 `git init` + `.gitignore` + 首次提交；后续每次部署打 `vYYYYMMDD-N` tag                                  |
| **P0-2** | 数据库口令**硬编码** `packdef.h`：`root / jmx********(已轮换,见deploy/.env)`                                                     | 口令已随源码扩散进 `VCC项目档案` 与知识库文档，等于公开泄露 | ①**轮换口令**；②构建期注入（本方案 `Dockerfile` 用 `sed` 注入）；③推荐改为 `getenv()` 运行期读取（补丁见 §6）；④清理文档中的口令         |
| **P0-3** | **建表脚本缺失且字段不全**：代码 `INSERT INTO t_user(tel,password,name,email,icon,feeling)`，而文档里的 `CREATE TABLE` **没有 `email` 列** | 注册/登录直接 SQL 报错，服务不可用                 | 用 `deploy/schema.sql`（已补 `email` + 三个索引）                                                       |
| **P0-4** | 服务端**当前状态编译不过**：`src/makefile` 缺 `-lcrypt`；根目录空桩 `main.cpp` 参与编译会得到空程序                                              | `make` 失败或产出错误二进制                    | 用本方案 `Dockerfile` / `deploy-bare.sh` 中的编译命令（`-lpthread -lmysqlclient -lcrypt`，仅编译 `src/*.cpp`） |
| **P1-1** | 服务端**两份副本**（`PlayerHallServer/` 与 `PlayerHallServer1/`）内容不一致                                                        | 构建源不确定，可能部署到缺 bcrypt 的旧版             | 确认 `PlayerHallServer/` 为唯一权威源，删除或归档 `PlayerHallServer1/`                                       |
| **P1-2** | 客户端 IP 硬编码 + 三份 `config.ini` 不一致（`.130`/`.129`/`.126.1`）                                                            | 换环境必连错服务器                            | 部署时统一由 `pack_client.bat` 生成 `config.ini`（模板见 `config.ini.example`）                             |
| **P1-3** | 目标环境不可达、无 SSH/MySQL 凭据                                                                                              | 无法就地验证                               | 先确认虚拟机是否开机、IP 是否变动；或改用方案 C（云服务器）                                                               |
| **P1-4** | 无健康检查、无备份、无回滚机制                                                                                                     | 出故障只能人工排查                            | 本方案提供 `verify.py` + `deploy.sh` 自动备份 + `rollback.sh`                                           |
| **P2-1** | **有状态会话**（登录态存内存 `m_mapIDToUserInfo`）                                                                               | 重启即全员掉线；**不能多实例水平扩展**                | 短期：单实例 + 维护窗口；长期：改 JWT（档案 §8.8 已有方案）                                                           |
| **P2-2** | 客户端 Windows-only（MinGW 32-bit），无打包脚本                                                                                | 分发靠手工拷 DLL                           | `pack_client.bat` 已提供                                                                          |
| **P2-3** | 三路 TCP 明文传输、无鉴权、无 TLS                                                                                               | 公网部署有安全与合规风险                         | 公网部署前必须加 TLS/鉴权；当前仅限内网                                                                         |

**修复顺序**：P0-1 → P0-2 → P0-3 → P0-4（这四个做完才能跑通首次部署）→ P1-1~P1-4 → P2。

## 四、构建与启动步骤

### 4.1 服务端（推荐 Docker Compose）

```bash
cd <项目目录>/deploy
cp .env.example .env            # 填写 DB_PWD / MYSQL_ROOT_PWD / CLIENT_SERVER_IP
./prepare.sh                    # 拷贝源码到 .staging（规避中文路径 + 清理空桩/教学 makefile）
docker compose build server     # 编译：g++ -std=c++11 -O2 -lpthread -lmysqlclient -lcrypt
docker compose up -d            # 启动 mysql + server
docker compose logs -f server   # 观察
```

`Dockerfile` 要点：构建期用 `sed` 把 `packdef.h` 里的 `_DEF_DB_*` 四个宏替换为注入值（源码不动，避免明文口令进仓库）；运行镜像只装 `libmysqlclient21 + libcrypt1 + netcat`；容器入口先 `nc -z mysql 3306` 探活再启动，避免 MySQL 未就绪时 `Open()` 直接 `exit(-1)`。

### 4.2 服务端（方案 B 裸机）

```bash
sudo ./deploy-bare.sh
```

脚本依次完成：装依赖 → 建库建用户 → 备份旧二进制 → 编译（含 `-lcrypt`）→ 安装到 `/opt/vcc` → 安装并启动 systemd → `ufw allow 8000` → 冒烟验证。

### 4.3 客户端

```bat
rem 修改 pack_client.bat 里的 QT_BIN / BUILD_DIR / SERVER_IP，然后运行
pack_client.bat
```

产出 `deploy\dist\VCC\`（`vcc-client.exe` + Qt/FFmpeg/SDL/Opus DLL + `config.ini`），压缩即可分发。

## 六、推荐改造：让配置走运行期环境变量（消除 P0-2 根因）

`include/packdef.h` 改为（保留原值作为兜底，完全向后兼容）：

```cpp
/*-------------数据库信息-----------------*/
static inline const char* _env(const char* key, const char* def){
    const char* v = getenv(key); return (v && *v) ? v : def;
}
#define _DEF_DB_NAME    _env("DB_NAME", "vcc")
#define _DEF_DB_IP      _env("DB_IP",   "localhost")
#define _DEF_DB_USER    _env("DB_USER", "vcc")
#define _DEF_DB_PWD     _env("DB_PWD",  "")      // 不再存放任何真实口令
```

改完后：`Dockerfile` 里的 `RUN sed ...` 整段可删除，改为 `docker compose` 的 `environment:` 注入，密钥不再进入镜像层。

## 八、替代方案对比与推荐

| 方案                        | 适用场景                     | 优点                                                                              | 缺点                                     |
| ------------------------- | ------------------------ | ------------------------------------------------------------------------------- | -------------------------------------- |
| **A. Docker Compose（推荐）** | 绝大多数场景：本地虚拟机、云服务器、内网服务器  | 一条命令起全套（含 MySQL）；环境一致可复现；构建/运行分离，镜像体积小；`restart: unless-stopped` 自带守护；回滚只需换 tag | 需要装 Docker；镜像内含构建期注入的 DB 口令（建议按 §6 改造） |
| **B. 裸机 + systemd**       | 目标机不便装 Docker；与现有虚拟机习惯一致 | 依赖最少；性能无损耗；`systemd` 托管自启与限流重启                                                  | 环境需手工维护，换机要重装；回滚靠手工备份二进制               |
| **C. 云服务器 + Compose**     | 需要外网/异地访问                | 有公网 IP，多端可连                                                                     | 必须补 TLS 与鉴权（当前协议明文）；需配安全组；有暴露面风险       |
| **D. 只分发客户端、服务端继续跑本机**    | 演示                    | 零成本                                                                             | 无高可用，关机即停；不建议作为正式部署                    |

**推荐 A**，理由：本项目最大的痛点是"环境不可复现 + 无回滚"。Compose 把 MySQL 版本、编译依赖、启动顺序、健康检查全部固化成文件，配合 `IMAGE_TAG` 即可实现"一键发布 / 一键回退"，且后续迁移到云服务器时同一份 `docker-compose.yml` 可直接复用（只需改 `CLIENT_SERVER_IP`）。

## 九、部署后验证

### 9.1 自动冒烟（协议级，推荐）

```bash
python3 verify.py --host 127.0.0.1 --port 8000
```

按 `packdef.h` 组包完成 **TCP 连通 → 注册 → 登录** 三步，一次性验证：进程存活、epoll 接收、MySQL 读写、bcrypt 哈希校验。输出示例：

```
✓ [1/3] TCP 连通 127.0.0.1:8000
✓ [2/3] 注册成功 (tel=139xxxxxx)
✓ [3/3] 登录成功 (userid=3, result=2)
```

### 9.2 数据层验证

```bash
docker exec -it vcc-mysql mysql -uroot -p -e \
  "SELECT id,tel,name,email,LEFT(password,7) AS alg FROM vcc.t_user ORDER BY id DESC LIMIT 5;"
# 期望：password 以 $2b$12$ 开头，说明 bcrypt 生效（不再是 MD5 明文）
```

### 9.3 容器/服务状态

```bash
docker inspect -f '{{.State.Health.Status}}' vcc-server   # 期望 healthy
nc -zv <服务端IP> 8000                                        # 期望 succeeded
```

### 9.4 客户端实测清单（端到端）

1. 复制 `dist\VCC\` 到客户端机器，确认 `config.ini` 的 `ip` 正确；
2. 启动 → 注册新账号 → 登录 → 进入房间；
3. 两台客户端进入同一房间，验证：**音频可听见、视频画面出现、成员列表正确**；
4. 退出房间 → 服务端无崩溃（`docker compose ps` 仍为 `Up`）；
5. 会议室满 2 人以上时观察 CPU/内存（20 人以上需按档案 §8.8 做 SFU 改造）。

## 十、回滚方案

| 层级      | 触发条件                 | 操作                                                                                                         | 耗时     |
| ------- | -------------------- | ---------------------------------------------------------------------------------------------------------- | ------ |
| **应用**  | 冒烟失败 / 客户端连不上 / 功能回归 | `./rollback.sh`（读取 `.last_good_tag` 重建 server 容器）                                                          | <1 min |
| **数据库** | 迁移导致数据异常             | `./rollback.sh --db backups/db-<时间戳>.sql`                                                                  | <3 min |
| **裸机**  | systemd 部署失败         | `cp /opt/vcc/playerhallserver.bak-* /opt/vcc/playerhallserver && systemctl restart playerhallserver` | <1 min |
| **客户端** | 新客户端不可用              | 分发上一版 `dist\VCC\` 压缩包                                                                                   | 视分发方式  |


**回滚前置保障**

- 每次 `deploy.sh` 自动 `mysqldump` 到 `deploy/backups/db-<时间戳>.sql` 并记录 `.last_good_tag`；
- 保留最近 **3 个** 镜像 tag 不清理（`docker images vcc-server`）；
- **禁止** 在 `docker compose down -v` 中使用 `-v`（会删除 MySQL 数据卷）；
- 灰度建议：先停服 → 备份 → 部署 → 冒烟 → 恢复对外，维护窗口 5 分钟内。

### 12.2 环境准备（目标机此前完全不具备）

1. 本机无 Docker、未启用 WSL → 安装 **Docker Desktop 29.8.2**（静默安装，退出码 0）；
2. 引擎起不来，报 `Docker Desktop is unable to start` → 根因是 **WSL 平台未安装**（`wsl -l -v` 报无分发，`wsl --install` 走商店通道失败）→ 手动下载安装 **WSL 3.0.3**（`wsl.3.0.3.0.x64.msi`），随后引擎 20 秒内就绪；
3. 构建时 `registry-1.docker.io` 连接超时（无代理）→ 配置 `~/.docker/daemon.json` 的 `registry-mirrors`：`docker.1panel.live` / `docker.m.daocloud.io` / `docker.1ms.run`，重启 Docker 后 `ubuntu:22.04`、`mysql:8.0` 均拉取成功。
