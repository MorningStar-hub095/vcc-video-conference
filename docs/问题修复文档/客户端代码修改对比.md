## 修改 4：usershow.cpp（H264 崩溃修复 - 核心修复）

> 本部分为 H264 视频编码崩溃修复的核心修改。启用 H264 编码后，客户端在第一帧编码发送完成后立即崩溃，根因是 `slot_setImage` 中 QImage 浅拷贝（Qt 隐式共享）在多线程环境下导致竞态条件。详细分析参考 [H264视频崩溃修复报告.md](file:///问题修复文档/H264视频崩溃修复报告.md)。

### 改动 ⑨ slot_setImage QImage 浅拷贝改为深拷贝

**位置**：`UserShow::slot_setImage` 函数

**原代码：**
```cpp
void UserShow::slot_setImage(QImage &img)
{
    m_img = img;  // 浅拷贝：m_img 与 img 共享同一块像素数据
    m_lastTime = QTime::currentTime();
    this->update();
}
```

**修改后：**
```cpp
void UserShow::slot_setImage(QImage &img)
{
    // [修复] 使用深拷贝而非浅拷贝，防止 paintEvent 中 scaled()
    //       访问已释放的共享像素数据
    // 原Bug: m_img = img 是浅拷贝（Qt隐式共享），m_img 与 img 共享同一块像素数据。
    //        slot_sendVideoFrame 返回后 img 被销毁，引用计数减少。
    //        paintEvent 中 m_img.scaled() 读取像素数据时，如果引用计数管理出现
    //        并发问题（video线程可能正在创建新的QImage影响共享数据），会导致读取
    //        已释放内存 → 崩溃。
    // 修复: m_img = img.copy() 创建深拷贝，m_img 拥有完全独立的像素数据缓冲区，
    //       不受其他 QImage 生命周期影响。
    m_img = img.copy();
    m_lastTime = QTime::currentTime();

    // [修复] 切换到 QImage 模式时隐藏 YuvGLWidget，防止 GL 渲染层覆盖
    if (m_glWidget) {
        m_glWidget->hide();
    }
    this->update();
}
```

**说明**：
1. **核心修复**：`m_img = img`（浅拷贝）改为 `m_img = img.copy()`（深拷贝）
2. **根因**：Qt 隐式共享在多线程环境下（Video线程创建QImage + Main线程paintEvent读取 + Worker线程delete[]堆操作），paintEvent中 `m_img.scaled()` 读取共享像素数据时发生竞态条件，访问已释放内存导致崩溃
3. 新增 `m_glWidget` 隐藏逻辑，防止 GL 渲染层覆盖 QImage 绘制

### 改动 ⑩ paintEvent 安全性增强

**位置**：`UserShow::paintEvent` 函数

**原代码：**
```cpp
void UserShow::paintEvent(QPaintEvent *event)
{
    QPainter painter( this );
    painter.setBrush( QBrush( Qt::black ) );
    painter.drawRect( 0, 0, this->width(), this->height() );

    if( m_img.size().height()<=0 ) return;

    m_img = m_img.scaled( this->width() , this->height() - ui->lb_name->height(),
                          Qt::KeepAspectRatio );
    int x = this->width() - m_img.width();
    x = x/2;
    int y = this->height() - m_img.height() - ui->lb_name->height();
    y = ui->lb_name->height() + y/2;
    QPixmap pix = QPixmap::fromImage( m_img );
    painter.drawPixmap( x , y , pix );
    painter.end();
}
```

**修改后：**
```cpp
void UserShow::paintEvent(QPaintEvent *event)
{
    QPainter painter( this );
    // 画黑色背景
    painter.setBrush( QBrush( Qt::black ) );
    painter.drawRect( 0, 0, this->width(), this->height() );

    // [修复] 当 YuvGLWidget 可见时（H264远程视频模式），跳过 QImage 绘制
    if (m_glWidget && m_glWidget->isVisible()) {
        painter.end();
        return;
    }

    if( m_img.size().height()<=0 ) return;

    // [修复] 添加 ui->lb_name 空指针检查和目标尺寸有效性检查
    int labelH = (ui->lb_name) ? ui->lb_name->height() : 20;
    int targetW = this->width();
    int targetH = this->height() - labelH;
    if (targetW <= 0 || targetH <= 0) {
        painter.end();
        return;
    }
    m_img = m_img.scaled(targetW, targetH, Qt::KeepAspectRatio);

    int x = this->width() - m_img.width();
    x = x/2;
    int y = this->height() - m_img.height() - labelH;
    y = labelH + y/2;
    QPixmap pix = QPixmap::fromImage( m_img );
    painter.drawPixmap( x , y , pix );
    painter.end();
}
```

**说明**：
1. 新增 `m_glWidget` 可见性检查，H264 远程视频模式下跳过 QImage 绘制
2. `ui->lb_name` 空指针检查：`(ui->lb_name) ? ui->lb_name->height() : 20`，防止 UI 文件变更后空指针崩溃
3. 目标尺寸有效性检查：`if (targetW <= 0 || targetH <= 0) return`，防止窗口最小化时 0 尺寸传入 `scaled()`
4. `labelH` 局部变量复用，减少重复调用

## 修改 7：ckernel.cpp（H264 编码相关）

### 改动 ⑭ 编码器重初始化：close()+init() → delete+new

**位置**：`ckernel::slot_startVideo` 函数

**原代码：**
```cpp
m_h264Encoder->close();
bool initOk = m_h264Encoder->init(encWidth, encHeight, encFps, encBitrate);
```

**修改后：**
```cpp
// [修复] 销毁旧实例，创建全新实例
// 原代码 close()+init() 在同一对象上重初始化，
// FFmpeg 全局状态可能被污染，新的 SwsContext 在 sws_scale 时可能访问损坏内存
delete m_h264Encoder;
m_h264Encoder = new H264Encoder(this);
bool initOk = m_h264Encoder->init(encWidth, encHeight, encFps, encBitrate);
```

**说明**：`close()` 释放 `codecCtx` 后，FFmpeg 全局状态可能被污染。在同一对象上调用 `init()` 创建的新 `SwsContext` 在 `sws_scale` 时可能访问损坏内存。使用 `delete + new` 创建全新实例，确保无残留状态。

### 改动 ⑮ Lambda 捕获 QImage 深拷贝

**位置**：`ckernel::slot_sendVideoFrame` 函数

**原代码：**
```cpp
QTimer::singleShot(0, this, [this, img]() {
    encodeAndSendVideoFrame(img);
});
```

**修改后：**
```cpp
// [修复] 深拷贝捕获，独立像素数据
// 原代码 [this, img] 捕获 img 是浅拷贝（Qt 隐式共享）
// lambda 被投递到事件队列后，摄像头线程可能在 lambda 执行前
// 释放或修改 img 的底层像素数据，导致 encode() 中访问已释放内存
QImage imgCopy = img.copy();  // 深拷贝，独立像素数据
QTimer::singleShot(0, this, [this, imgCopy]() {
    encodeAndSendVideoFrame(imgCopy);
    m_encodingPending = false;
});
```

**说明**：`[this, img]` 捕获 `img` 是浅拷贝（Qt 隐式共享）。lambda 被投递到事件队列后，摄像头线程可能在 lambda 执行前释放或修改 `img` 的底层像素数据，导致 `encode()` 中访问已释放内存。改用 `img.copy()` 深拷贝捕获。
