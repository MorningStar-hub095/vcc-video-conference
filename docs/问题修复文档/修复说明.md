# 客户端登录/注册提交按钮无响应 - 修复说明

## 问题现象
客户端运行后，在登录和注册界面点击"提交"按钮，应该出现提示框或跳转到创建房间界面，但实际点击后毫无反应。

## 根本原因

### 原因 1：构造函数中阻塞式 connect() 导致 UI 冻结
`ckernel.cpp` 构造函数中调用了 3 次 `OpenNet()`，而 `TcpClient::InitNet()` 使用的是阻塞式 socket 的 `connect()`。
当服务器未启动时（默认 IP `192.0.2.129` 是 VMware 虚拟机地址），每次 `connect()` 会阻塞约 21 秒，
3 次累计卡顿约 63 秒。此时：
- 登录窗口已 `show()` 但 `a.exec()` 事件循环尚未启动
- 窗口看起来显示了，但完全无法响应任何点击（包括提交按钮）

### 原因 2：点击提交时再次阻塞
即使 UI 可交互后，点击提交按钮：
1. `on_pb_commit_clicked()` 校验通过 → 发射 `SIG_loginCommit`
2. `slot_loginCommit()` 调用 `m_pClient->SendData(...)`
3. `TcpClientMediator::SendData()` 发现未连接，**同步重连**（再阻塞 ~21 秒）
4. 重连失败后静默返回 -1，**没有任何提示框，也没有跳转**——这就是"毫无反应"的直接表现

### 原因 3：AV 客户端信号连接错误
`ckernel.cpp` 构造函数的 for 循环里，信号连接的是 `m_pClient` 而不是 `m_pAVClient[i]`，
导致音视频客户端的数据无法正确接收。

### 原因 4：服务器 IP 宏不一致
两个不同的宏指向不同 IP：
- `packdef.h` 中 `_DEF_SERVERIP` = `"192.0.2.1"`
- `INetMediator.h` 中 `_DEF_SERVER_IP` = `"192.0.2.129"`

导致 `m_pClient` 连 `.129`，`m_pAVClient` 连 `.1`，连到了不同地址。

## 修复内容

### 文件 1：ckernel.cpp

#### 改动 ① 新增头文件（第 7 行后）
```cpp
#include <thread>
```

#### 改动 ② 构造函数中网络初始化部分
**原代码：**
```cpp
m_pClient = new TcpClientMediator;
m_pClient->OpenNet(m_serverIP.toStdString().c_str());
connect(m_pClient , SIGNAL(SIG_ReadyData(uint,char*,int)),this , SLOT(slot_dealData(uint,char*,int)));

//音频和视频的链接
for( int i = 0 ; i < 2 ; i++ )
{
    m_pAVClient[i] = new TcpClientMediator;
    m_pAVClient[i]->OpenNet( _DEF_SERVERIP , _DEF_PORT );
    connect(m_pClient , SIGNAL(SIG_ReadyData(uint,char*,int)),this , SLOT(slot_dealData(uint,char*,int)));
}
```

**改为：**
```cpp
m_pClient = new TcpClientMediator;
connect(m_pClient , SIGNAL(SIG_ReadyData(uint,char*,int)),this , SLOT(slot_dealData(uint,char*,int)));

//音频和视频的链接
for( int i = 0 ; i < 2 ; i++ )
{
    m_pAVClient[i] = new TcpClientMediator;
    //修复：原来错误地连接了 m_pClient，应该连接 m_pAVClient[i]
    connect(m_pAVClient[i] , SIGNAL(SIG_ReadyData(uint,char*,int)),this , SLOT(slot_dealData(uint,char*,int)));
}

//修复：网络初始化（阻塞式 connect）放到子线程执行，避免主线程阻塞导致 UI 无响应
std::thread([this](){
    m_pClient->OpenNet(m_serverIP.toStdString().c_str());
    for( int i = 0 ; i < 2 ; i++ )
    {
        m_pAVClient[i]->OpenNet( _DEF_SERVER_IP , _DEF_PORT );
    }
}).detach();
```

**修复了 3 个问题：**
1. `OpenNet` 移入子线程，避免阻塞式 `connect()` 卡死 UI
2. for 循环里 `connect(m_pClient, ...)` 改为 `connect(m_pAVClient[i], ...)`
3. `_DEF_SERVERIP` 改为 `_DEF_SERVER_IP`，统一 IP

#### 改动 ③ slot_loginCommit 函数开头新增连接检查
```cpp
//修复：检查网络连接状态，未连接时提示用户，避免 SendData 内部阻塞重连导致 UI 卡死
if( !m_pClient || !m_pClient->IsConnected() )
{
    QMessageBox::about(m_pLoginDlg, "提示", "网络未连接，请检查服务器是否启动后重试");
    return;
}
```

#### 改动 ④ slot_registerCommit 函数开头新增同样的连接检查
```cpp
//修复：检查网络连接状态，未连接时提示用户，避免 SendData 内部阻塞重连导致 UI 卡死
if( !m_pClient || !m_pClient->IsConnected() )
{
    QMessageBox::about(m_pLoginDlg, "提示", "网络未连接，请检查服务器是否启动后重试");
    return;
}
```

### 文件 2：packdef.h

#### 改动 ⑤ 第 12 行 IP 地址统一
**原代码：**
```cpp
#define _DEF_SERVERIP   ("192.0.2.1")
```

**改为：**
```cpp
#define _DEF_SERVERIP   ("192.0.2.129")
```

与 `INetMediator.h` 中的 `_DEF_SERVER_IP` 保持一致。

## 修复效果对比

| 问题 | 修复前 | 修复后 |
|------|--------|--------|
| UI 冻结 | 构造函数 3 次阻塞 connect，卡 ~63 秒 | 网络初始化在子线程，UI 立即可交互 |
| 信号连接错误 | AV 客户端数据发到错误的 m_pClient | 正确连接到 m_pAVClient[i] |
| 点击提交无反应 | SendData 静默阻塞重连，无提示 | 弹出"网络未连接"提示框 |
| IP 不一致 | m_pClient 连 .129，m_pAVClient 连 .1 | 全部统一为 .129 |

## 重要提醒

1. **服务器必须启动**：如果你的服务器 IP 不是 `192.0.2.129`，请同步修改：
   - `packdef.h` 的 `_DEF_SERVERIP`
   - `INetMediator.h` 的 `_DEF_SERVER_IP`
   - 或在程序运行目录下创建 `config.ini` 配置文件指定正确的 IP

2. **config.ini 格式示例**：
   ```ini
   [Net]
   ip=192.0.2.129
   ```

3. **验证服务器连通性**（PowerShell）：
   ```powershell
   Test-NetConnection -ComputerName 192.0.2.129 -Port 8000
   ```
   如果 `TcpTestSucceeded` 不是 True，说明服务器没开——这就是"毫无反应"的直接原因。
