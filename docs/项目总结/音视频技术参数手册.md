### 1.5.1 动态阈值参数（噪声 EMA 三档自适应）

为适配不同环境噪声，AudioRead 通过 QTimer 每 5 秒评估一次噪声 RMS 的 EMA（指数移动平均），据此在 WebRTC VAD 的 1/2/3 三档间自适应切换灵敏度。核心成员包括 `m_vadMode`（当前模式）、`m_noiseLevel`（瞬时 RMS）、`m_noiseLevelEMA`（噪声 EMA）、`m_consecutiveSilentFrames`/`m_consecutiveSpeechFrames`（连续帧计数）、`m_currentMuteState`/`m_pendingMuteState`（状态平滑）、`m_vadAdjustTimer`（QTimer*）。

| 参数 | 值 | 说明 |
|------|-----|------|
| 评估周期 | 5 秒 | QTimer 主线程触发 `slot_adjustVadMode()` |
| 噪声 EMA 平滑系数 α | 0.95 | `m_noiseLevelEMA = 0.95×old + 0.05×new` |
| RMS 计算 | `calculateRMS(int16_t*, int) → float` | 归一化到 0~1 |
| 噪声 RMS 写入线程 | SDL 音频线程（audioCallback） | 每帧计算更新 `m_noiseLevel` |
| 噪声 RMS 读取线程 | 主线程（slot_adjustVadMode） | 单 float 良性跨线程读取 |
| 模式 1（宽松）触发条件 | EMA < 0.02 | 安静环境，提高灵敏度 |
| 模式 2（中等）触发条件 | 0.02 ≤ EMA < 0.10 | 中等噪声，VoIP 推荐档 |
| 模式 3（严格）触发条件 | EMA ≥ 0.10 | 嘈杂环境，降低误触发 |
| 模式切换策略 | 仅模式变化时调用 `WebRtcVad_set_mode` | 避免无谓重置 |

> **线程模型说明：** audioCallback 运行在 SDL 音频线程，负责计算 RMS 并更新 `m_noiseLevel`、连续帧计数，状态切换时 `Q_EMIT SIG_muteStateChanged`（跨线程 QueuedConnection 到主线程）；QTimer 在主线程触发 `slot_adjustVadMode` 读取 `m_noiseLevel`（单 float 良性跨线程）；`ckernel::slot_muteStateChanged` 在主线程接收信号并调用 `RoomDialog::updateMuteStatus` 更新 UI（静音时 cb_audio 文本变"音频(无声)"并置灰，有声时恢复"音频"）。

### 1.6 音频数据流全链路

```
麦克风硬件
    ↓ (模拟信号)
操作系统音频驱动
    ↓ (PCM数字信号)
SDL2音频线程回调 (20ms/960samples)
    ↓ (AUDIO_S16LSB 48kHz 单声道 PCM)
WebRTC VAD静音检测(VAD) (返回0/1) + calculateRMS 更新噪声 RMS
    ↓ (状态平滑：连续 3 帧确认(≈60ms) 后 Q_EMIT SIG_muteStateChanged)
    ↓ (静音帧 PCM memset 清零；模式由主线程 QTimer 5s 动态阈值自适应)
ckernel::slot_muteStateChanged → RoomDialog::updateMuteStatus (UI 反馈 cb_audio)
    ↓
Opus编码器 (VOIP模式 32kbps DTX+FEC，静音帧清零 + DTX 双重压缩)
    ↓ (60-120字节/帧 编码数据)
ckernel::slot_audioFrame()
    ↓ (构造STRU_AUDIOFRAME包)
AVSyncManager::updateLocalAudioClock(pts)
    ↓ (更新本地音频时钟)
TCP音频连接发送 (连接2)
    ↓
服务端透明转发
    ↓
TCP音频连接接收
    ↓
ckernel::slot_dealAudioFrameRq()
    ↓ (解析Opus数据)
AVSyncManager::updateAudioClock(userId, pts)
    ↓ (更新远端音频时钟)
AudioWrite::slot_playAudio(opusData)
    ↓ (mutex加锁入队deque)
SDL2音频播放线程回调 (20ms)
    ↓ (mutex加锁出队)
Opus解码器 (960samples → 1920字节PCM)
    ↓
SDL_MixAudioFormat混音播放
    ↓
扬声器硬件
```

> **[崩溃修复] FFmpeg 帧缓冲区管理标准化：**
> 原方案使用 `av_image_alloc` 手动分配像素缓冲区，绕过了 AVFrame 引用计数机制，不支持 `av_frame_make_writable`，且释放路径与 `av_frame_free` 不一致，易内存泄漏。修复后改为 `av_frame_get_buffer` + `av_frame_make_writable` 标准组合，缓冲区由 AVFrame 内部管理，引用计数自动维护，多线程安全。详见 `问题修复文档\H264视频崩溃修复报告.md`。
>
> **[工具链确认] FFmpeg DLL 编译工具链：**
> 经 DLL 依赖分析确认，项目所用的 FFmpeg DLLs（avcodec-58.dll、avutil-56.dll、swscale-5.dll 等）是 MinGW 编译的 Zeranoe 构建（依赖 `msvcrt.dll`，非 MSVC 的 `vcruntime140.dll`），与项目 MinGW 32-bit 工具链完全兼容，`sws_scale` 可安全使用。导入库使用 `.dll.a` 格式（MinGW 标准），非 `.lib` 格式（MSVC）。

#### 2.9.2 BT.601 YUV→RGB 转换矩阵

```glsl
// Fragment Shader核心代码

float u = texture2D(tex_u, v_texCoord).r - 0.5;  // U分量 [-0.5, 0.5]
float v = texture2D(tex_v, v_texCoord).r - 0.5;  // V分量 [-0.5, 0.5]

// BT.601标准转换矩阵
R = Y + 1.402 × Cr
G = Y - 0.344136 × Cb - 0.714136 × Cr
B = Y + 1.772 × Cb
```

### 7.4 线程安全与稳定性保障（v1.1 新增）

> 本节记录 H264 视频崩溃修复中发现的线程安全问题及保障措施。崩溃最终根因为 QImage 隐式共享浅拷贝在多线程环境下引发的竞态条件。

#### 7.4.1 三线程架构与竞态风险

| 线程 | 职责 | 操作的 QImage | 风险 |
|------|------|--------------|------|
| Video线程 | 摄像头采集 | 由 cv::Mat 构造 QImage，像素数据在堆上分配 | 创建后 emit 信号传递 |
| Main线程 | UI渲染 + 编码调度 | paintEvent 中 m_img.scaled() 读取像素数据 | 读取已释放内存 → SIGSEGV |
| Worker线程 | 异步编码 | encode() 中访问 QImage 像素数据 | 读取已释放内存 → SIGSEGV |

#### 7.4.2 Qt 隐式共享（Implicit Sharing）机制

| 操作 | 拷贝类型 | 引用计数 | 多线程安全 |
|------|---------|---------|-----------|
| `m_img = img` | 浅拷贝 | refcount+1（共享像素数据） | ❌ 不安全（COW竞态） |
| `m_img = img.copy()` | 深拷贝 | 独立缓冲区（refcount=1） | ✅ 安全 |
| `[img]` Lambda值捕获 | 浅拷贝 | refcount+1 | ❌ 不安全 |
| `QImage imgCopy = img.copy()` + `[imgCopy]` | 深拷贝 | 独立缓冲区 | ✅ 安全（C++11兼容） |

#### 7.4.3 线程安全保障措施清单

| 修复点 | 文件 | 修复内容 | 优先级 |
|--------|------|---------|--------|
| slot_setImage 深拷贝 | usershow.cpp | `m_img = img` → `m_img = img.copy()` | P0（最终根因） |
| Lambda 捕获深拷贝 | ckernel.cpp | 捕获前 `QImage imgCopy = img.copy()` | P2（辅助） |
| paintEvent 防御检查 | usershow.cpp | ui->lb_name 空指针检查 + 尺寸有效性检查 | P2（辅助） |
| 编码防堆积 | ckernel.cpp | m_encodingPending 标志防止事件队列堆积 | P2（辅助） |
| 事件队列清理 | ckernel.cpp | QCoreApplication::removePostedEvents(this) 析构前清理 | P2（辅助） |
