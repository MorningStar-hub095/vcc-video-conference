MySQL 数据库 WeChat 库的实体关系模型，包含用户表结构及数据约束

一、ER 关系图

erDiagram t_user { int id PK "自增主键" varchar tel UK "手机号(唯一)" varchar password "MD5加盐哈希密码" varchar name "用户名" varchar email "邮箱(可选)" int icon "头像编号(默认1)" varchar feeling "个性签名(默认空)" }
设计说明：当前系统仅使用单表 t_user 存储用户信息。房间信息为内存态数据结构（服务端维护 roomId → list<userId> 映射），不持久化到数据库。

二、表结构详细说明

t_user 用户表
字段名数据类型约束默认值用途备注
idINTPK, AUTO_INCREMENT-用户唯一标识登录成功后返回给客户端，用于后续协议中的 userId 字段
telVARCHAR(60)UNIQUE, NOT NULL-登录手机号作为登录凭证，注册时检查唯一性
passwordVARCHAR(60)NOT NULL-密码哈希值存储 MD5(原始密码 + 盐值) 结果，服务端比对哈希值
nameVARCHAR(60)NOT NULL-用户名/昵称注册时填写，房间内显示
emailVARCHAR(60)-''邮箱地址可选字段，支持更新个人信息
iconINT-1头像编号对应客户端预设的头像资源编号
feelingVARCHAR(260)-''个性签名用户状态描述
