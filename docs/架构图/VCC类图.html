UML 关系符号说明

符号关系类型说明
<|--继承（泛化）子类继承父类，实线空心三角
<|..实现（接口）类实现接口，虚线空心三角
*--组合（Composition）强拥有关系，部分随整体创建/销毁，实线实心菱形
o--聚合（Aggregation）弱拥有关系，部分可独立于整体存在，实线空心菱形
-->关联（Association）类之间有结构关系，实线箭头
..>依赖（Dependency）类之间有使用关系，虚线箭头

10.1 三路 TCP 连接架构

ckernel ├── m_pClient (信令连接) ──→ TcpClientMediator ──→ TcpClient ──→ 服务器:8000 │ 用途: 登录/注册/房间管理/成员通知 │ 特点: 低频小包，要求即时响应 │ ├── m_pAVClient[0] (音频连接) ──→ TcpClientMediator ──→ TcpClient ──→ 服务器:8000 │ 用途: Opus 音频帧转发 │ 特点: 高频小包（50帧/秒），要求低延迟 │ └── m_pAVClient[1] (视频连接) ──→ TcpClientMediator ──→ TcpClient ──→ 服务器:8000 用途: H264 视频帧分片转发 特点: 中频大包（30帧/秒，4KB/分片），要求高吞吐
设计说明： 三路 TCP 连接分离信令与媒体流，避免大视频帧阻塞信令通道。每路连接独立的 TcpClientMediator 实例，通过 SIG_ReadyData 信号统一汇入 ckernel::slot_dealData 处理。

10.2 双路径视频渲染架构

ckernel::slot_sendVideoFrame(QImage) │ ├── H264 路径（m_useH264 = true） │ ├── H264Encoder::encode(QImage) → QByteArray │ ├── 按 4KB 分片 → STRU_VIDEO_FRAME_H264_HEADER + h264Data │ ├── SendVideoWorker 子线程发送 │ └── 接收端: H264Decoder::decode → AVFrame → YuvGLWidget GPU 渲染 │ └── JPEG 路径（m_useH264 = false，兼容回退） ├── QImage::save("JPG") → QByteArray ├── STRU_VIDEO_FRAME + jpegData └── 接收端: slot_refreshUser(QImage) → QPainter CPU 渲染
设计说明： H264 路径使用 GPU 加速渲染（YuvGLWidget + OpenGL Shader），JPEG 路径使用 CPU 软渲染（QPainter）。UserShow 控件通过 m_glWidget 的可见性自动切换渲染路径。

10.3 QImage 隐式共享线程安全

classDiagram direction LR class VideoThread { <<线程>> +MatToQImage 构造QImage +emit SIG_sendVideoFrame } class MainThread { <<线程>> +slot_setImage +paintEvent_scaled } class WorkerThread { <<线程>> +encodeAndSendVideoFrame +H264Encoder_encode } VideoThread ..> MainThread : SIG_sendVideoFrame VideoThread ..> WorkerThread : QTimer_singleShot note for MainThread "竞态风险点 QImage隐式共享COW\nm_img = img 浅拷贝 共享像素数据\npaintEvent读取时可能访问已释放内存\n修复方案 m_img = img.copy 深拷贝" note for WorkerThread "竞态风险点 Lambda捕获QImage\nthis img 浅拷贝捕获\n异步执行时可能访问已释放内存\n修复方案 QImage imgCopy = img.copy 深拷贝"
设计说明： Qt 的 QImage 采用隐式共享（Copy-On-Write）机制，赋值操作是浅拷贝。在三线程架构（Video/Main/Worker）中，浅拷贝会导致竞态条件：paintEvent 读取像素数据时，原始 QImage 可能已被销毁。修复方案是在 slot_setImage 和 Lambda 捕获前使用 img.copy() 强制深拷贝。

10.4 FFmpeg 帧缓冲区管理

H264Encoder::encode(QImage) 流程： │ ├── 1. QImage 深拷贝：img.copy() → 独立像素数据 ├── 2. av_frame_make_writable(m_frame) → 确保 YUV 帧缓冲区可写 ├── 3. sws_scale(m_swsCtx, RGB→YUV420P) → 色彩空间转换 ├── 4. avcodec_send_frame(m_codecCtx, m_frame) → 发送帧到编码器 └── 5. avcodec_receive_packet(m_codecCtx, m_pkt) → 接收编码后的包 H264Decoder::decode(QByteArray) 流程： │ ├── 1. avcodec_send_packet(m_codecCtx, m_pkt) → 发送包到解码器 ├── 2. avcodec_receive_frame(m_codecCtx, m_frame) → 接收解码后的帧 └── 3. av_frame_clone(m_frame) → 引用计数 +1，零拷贝跨线程传递
设计说明： 编码器使用 av_frame_get_buffer + av_frame_make_writable 标准组合管理帧缓冲区，支持引用计数。解码器使用 av_frame_clone 实现零拷贝跨线程传递，避免像素数据复制开销。
